## Summary

Create one self-contained public tutorial covering every public behavior
delivered by Plans 004.6a–d, plus concise examples of the three migrated CLI
workflows. Use disposable synthetic data, public APIs only, no saved outputs,
and no corrections to older notebooks.

## Notebook flow

### 1. Audience, prerequisites, and outline

- Explain content identity, current observations, active tags, and immutable
  queries.
- Link Plan 004.6 and the public query grammar.
- State that the tutorial covers file details, content details, vocabulary
  queries, retained reads, and CLI equivalents.

### 2. Disposable catalog setup

- Scaffold from the Jupyter tutorial template.
- Create an in-root catalog in a `TemporaryDirectory`.
- Seed duplicate files, unique and untagged content, user/system assertions,
  multiple tags, and a retracted-only tag.
- Scan once, remove one tagged path, and refresh to create historical-only
  content and useful scan history.
- Capture the post-setup source snapshot for the final read-only assertion.

### 3. Plan 004.6a — Current-file tag details

- Build an immutable bounded `files()` query using path/tag predicates and
  sorting.
- Compare the base `fetch()` with `with_tags(limit=...)`.
- Show complete file count, distinct-content count, and total size despite row
  and tag bounds.
- Demonstrate duplicate paths sharing one tag preview.
- Demonstrate provenance-restricted matching with unrestricted displayed tags.
- Compare bounded previews with `all_tags=True` and explain per-terminal scan
  pinning.

### 4. Plan 004.6b — Catalog-wide content and details

- Show `contents()` returning tagged, untagged, current, and historical-only
  identities in fixed identity order.
- Demonstrate exact content, all/any tag, and provenance predicates.
- Contrast bounded `fetch()` with complete `count()`.
- Add `with_details(root=...)` and show bounded current paths, complete path
  counts, active-tag previews, and `all_tags=True`.
- Show that an unknown valid root produces zero paths without removing
  catalog-wide content matches.
- Reuse the base query to reinforce immutability and lazy evaluation.

### 5. Plan 004.6c — Active tag vocabulary

- Demonstrate default name ordering and complete `count()`.
- Sort by content and assertion usage with deterministic name ties.
- Apply user/system provenance and show that all metrics change with scope.
- Compose two regex predicates to demonstrate AND plus Python `re.search`
  semantics.
- Confirm orphaned-content tags remain visible and retracted-only tags do not.

### 6. Plan 004.6d — Retained exact and historical reads

- Demonstrate `current_scan`, `current_summary`, `content_for_path`,
  `tags_for_path`, and `tags_for_content`.
- Consume `scan_history` and `observation_history` in deterministic order.
- Partially consume a history iterator inside `contextlib.closing`, then show
  the catalog remains usable.
- Explain that these signatures stayed stable while their SQL execution moved
  behind the private compiler/executor boundary.

### 7. Concise CLI parity

Invoke the CLI entry point once for each migrated workflow and assert a
successful exit code:

- tag-aware `catalog files`;
- `catalog tags find`;
- regex/sorted `catalog tags available`.

Do not reproduce the full CLI option matrix; the notebook teaches the typed
Python API first and uses CLI cells only to demonstrate parity.

### 8. Exercise, pitfalls, and cleanup

- Exercise: build a provenance-restricted content query with bounded details
  and a related vocabulary query.
- Follow it with an executable answer cell and assertions.
- Call out bounds versus totals, content-level tags, root-only path scope,
  all-provenance previews, separate-terminal snapshots, and explicit history
  iterator cleanup.
- Assert that the read demonstrations and CLI queries did not change source
  files.
- Close the catalog and remove the temporary directory.
