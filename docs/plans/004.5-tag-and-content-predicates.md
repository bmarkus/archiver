# Plan 004.5 — Tag and Content Predicates

Status: Implemented (approved).
Parent: [004](004-query-grammar-and-api-refactor.md).
Depends on: [004.4](004.4-grouped-queries-and-duplicates.md).
Created: 2026-09-09. Implemented: 2026-09-09. Reviewed: 2026-09-29.

## Goal and contract

Extend CurrentFileQuery with content.is_(), tags.all_of(), tags.any_of() and
distinct_content_count() according to the
[final API contract](004-public-api-target.md). Preserve all existing terminals
and their bounds, ordering, and laziness. Exact content lookup is included here
because 004.6a must replace find_by_content without a second filtering path.

## Implementation boundary

Extend the immutable predicate union and private compiler using the existing
query modules. Reuse one active-assertion matching helper that can later serve
content queries. Use EXISTS or equivalent distinct-content semantics so
multiple assertions never multiply file rows or totals. Apply provenance to
each requested tag. Compile distinct content reduction in SQLite over the full
filtered current set, with no display limit or ordering.

Do not introduce detail views, content/vocabulary constructors, API removals,
CLI migration, new tag mutations, schema changes, or arbitrary predicate logic.
Existing legacy searches can remain until their owning 004.6 subplan.

## Acceptance tests

- All/any, repeated tags, invalid/empty names, invalid provenance/type, exact
  full content IDs, and rejection of cross-domain expressions.
- Same content at duplicate paths gets the same tag match but remains separate
  file rows; distinct_content_count counts that identity once.
- Independent provenance satisfaction per requested tag; multiple producers,
  retractions, untagged content, empty files, and no matches.
- Path/content/tag predicate composition and repeated AND; every row terminal,
  count, size, and distinct-content reduction uses the same filtering.
- SQL parameterization, pre-materialization bounds, complete pre-limit totals.
- Lazy reuse after scans and assertion/retraction changes, failed/interrupted
  scan isolation, closed catalog errors, and read-only success/failure.
- Existing CLI and query regression tests pass.

## Implementation outcome

- Added immutable `content.is_(ContentId)`, `tags.all_of()`, and
  `tags.any_of()` predicates to the public `archiver.query` vocabulary.
  Tag factories require at least one valid name, deduplicate and sort names,
  and accept only `None`, `"user"`, or `"system"` provenance.
- Extended `CurrentFileQuery.where()` and the internal current-observation
  description to retain typed path, content, and tag predicates with repeated
  logical-AND composition.
- Compiled exact content matching by complete algorithm and digest. Compiled
  active-tag matching through one reusable distinct-content selection helper;
  retracted assertions are excluded, provenance applies to every requested
  tag, and multiple producers cannot multiply file rows or totals.
- Added `CurrentFileQuery.distinct_content_count()` as a complete SQLite
  reduction that shares all query predicates and ignores ordering and the
  display limit.
- Updated the public query grammar with content/tag filtering, provenance,
  composition, and distinct-content reduction examples.
- Added [a public Plan 004.5 tutorial](../../notebooks/public/plan-004.5-tag-and-content-predicates.ipynb)
  covering immutable predicates, complete expansion of one selected content
  identity, tag and provenance semantics, composed filters, complete
  reductions, lazy tag-state changes, an exercise, pitfalls, and cleanup using
  disposable synthetic files and public APIs.
- Added unit and integration coverage for immutable/canonical expressions,
  invalid values and cross-domain expressions, SQL parameterization and
  bounds, exact content matching, all/any and provenance semantics, duplicate
  paths, multiple producers, retractions, untagged and empty content, repeated
  predicate composition, every row terminal and reduction, lazy state changes,
  failed/interrupted scans, closed catalogs, and read-only success/failure.
- User-visible behavior: current-file queries can now filter by exact content
  identity and active tags and can count distinct matching content identities.
- Schema changes: none; schema version remains 2.
- Architectural decision: active-tag predicates compile to a reusable query
  selecting distinct matching content row IDs, allowing later content queries
  to share semantics without joining assertion rows into file results.
- Deviations: none. The separately recorded historical public-notebook
  migration gap was not changed by this plan.
