## Goal

Expose Plan 002 reconciliation through a safe command-line preview and atomic refresh workflow. A preview observes and reports filesystem differences without changing catalog state; an applied refresh observes again and atomically persists its snapshot.

## Command interface

```text
archiver catalog refresh ROOT [--dry-run] [--details {changes,all}] [--no-progress] [--progress-every FILES]
archiver catalog scan ROOT [--dry-run] [--details {changes,all}] [--no-progress] [--progress-every FILES]
```

- `refresh` reconciles the root and, unless `--dry-run` is supplied, applies the resulting change set atomically.
- `--dry-run` performs no SQLite writes and never changes the current scan.
- Default output reports aggregate new, unchanged, modified, and missing counts. `--details changes` prints changed-path rows; `--details all` also prints unchanged paths and whether their SHA-256 identity was reused from matching metadata or rechecked.
- `scan` is a compatibility alias for `refresh`; both commands have identical behavior and output.
- Reconciliation, application, and stale-baseline failures return a nonzero exit code without replacing current state.

## Design decisions

- A dry-run change set remains process-local. An applied command always reconciles immediately before application rather than persisting a preview plan across invocations.
- Detail rows preserve the reconciliation order, which is deterministic by relative POSIX path.
- Existing interactive progress behavior applies during reconciliation for both commands. The `.archiver` control directory remains excluded.
- No schema changes, JSON output, or separate persistent `apply` command are introduced.
