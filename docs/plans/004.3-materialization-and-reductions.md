## Goal

Expand the current-file grammar beyond its bounded `fetch()` terminal. A
filtered `Catalog.files(root)` query must support the existing current-file
materializations and reductions without retaining a separate
`search_current_files()` aggregate-query engine.

This subplan preserves the observation-preserving query domain established by
Plans 004.1 and 004.2. It does not add fields, predicates, projections,
grouping, historical queries, or tag semantics.

## Public API

Keep the immutable source and transformation API unchanged:

```python
query = catalog.files(root).where(path.glob("nested/*.txt")).sort(size.desc()).limit(10)
```

Add these terminals to `CurrentFileQuery`:

```python
query.fetch()  # tuple[FileObservation, ...], at most query.limit()
query.first()  # FileObservation | None
query.count()  # int
query.total_size_bytes()  # int
query.stream()  # Iterator[FileObservation], at most query.limit()
query.stream_all()  # Iterator[FileObservation], explicit and unbounded
```

`fetch()` retains its Plan 004.2 behavior. `first()` returns the first
matching observation under the query's effective ordering, or `None`; it does
not materialize a page. `count()` and `total_size_bytes()` describe the full
filtered current set, ignoring the query's display limit. An empty match set
has count `0` and total size `0`.

`stream()` preserves the query's order and positive row limit while yielding
typed observations one at a time. `stream_all()` preserves filtering and
ordering but deliberately removes the row bound. It is the only new public
unbounded terminal: its name makes unbounded consumption explicit, and no
`fetch_all()` or implicit unbounded collection is added.

All terminals are lazy until their execution or first iterator advancement,
require an open catalog, and resolve the location's latest successful scan at
that time. A query may therefore produce different results across separate
terminals if the catalog changes between them; this is existing Plan 004
semantics, not a snapshot guarantee.

## Existing API migration

Refactor `Catalog.search_current_files()` to construct one equivalent public
query and obtain its bounded rows, complete count, and complete size through
the grammar terminals. Preserve its signature, `CurrentFileSearch` result,
ordering, empty-root behavior, totals, and CLI output exactly.

Refactor `Catalog.current_files()` only if equivalence is established: it must
retain its unbounded `list[FileObservation]` compatibility contract by
materializing the explicit `stream_all()` terminal. Its public signature and
behavior must not change.

The existing historical `scan_history()` and `observation_history()` streams
remain distinct historical-query APIs. They are not migrated or generalized in
this subplan.

## Internal design

Extend the private compiler/executor boundary only as needed for these
terminals:

- centralize the current-location and latest-successful-scan relation plus
  typed path-predicate compilation, so row, reduction, and streaming paths do
  not duplicate filtering SQL;
- compile row ordering and SQL `LIMIT` only for bounded row terminals;
- compile `first()` with the effective ordering and SQL-side one-row bound;
- compile count and `COALESCE(SUM(size_bytes), 0)` reductions without row
  ordering or display limits;
- stream directly from the SQLite cursor without catalog-wide row
  materialization; and
- keep SQL identifiers and fragments private, bind all values as parameters,
  and materialize `FileObservation` in one shared narrow function.

The implementation must not introduce a general SQL framework, snapshots,
caching, pagination, async execution, another backend, or a persistent schema
change.

## Compatibility and safety

Preserve:

- byte-based content identity and path-scoped file observations;
- latest-successful-scan current-state semantics after successful, failed, or
  interrupted scans;
- deterministic ordering and the established path tie-breaker;
- schema version and all persisted tables/indexes;
- read-only source files and catalog data on successful and failing terminals;
- `current_files()`, `search_current_files()`, history APIs, tag-aware search,
  duplicate inspection, and CLI behavior unless explicitly migrated above.

No existing API is removed, renamed, or deprecated. No tag, content, size, or
mtime predicates; OR/NOT composition; projection; grouping; duplicate query;
historical grammar; CLI grammar construction; or public batch-unbounded
collection is in scope.

## Acceptance criteria

- One filtered current-file query provides bounded collection, first result,
  complete count, complete total size, bounded streaming, and explicit
  unbounded streaming.
- Reduction results describe all filtered current observations, never merely
  the bounded row page, and are computed by SQLite.
- Bounded terminals apply deterministic ordering and bounds in SQLite before
  observation materialization.
- No terminal exposes SQL, a cursor, a schema identifier, or an implicit
  unbounded collection API.
- `search_current_files()` delegates both its rows and reductions through the
  grammar while preserving its public and CLI contracts.
- `current_files()` remains compatible; history, tags, duplicates, and
  persistent schema remain unchanged.
- Required validation passes and the implementation outcome is recorded here.

## Implementation outcome

- Centralized current-state and path-predicate SQL compilation for row, reduction, and streaming terminals. Reductions execute in SQLite over the complete filtered set and ignore display bounds; `first()` executes with a SQL-side one-row bound.
- Migrated `Catalog.current_files()` to explicitly materialize `stream_all()` while retaining its `list[FileObservation]` compatibility result.
