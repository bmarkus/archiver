# Plan 001.4 - Streaming Scan Progress

**Status:** Planned  
**Parent plan:** [Plan 001 - Catalog Foundation](001-catalog-foundation.md)  
**Related subplan:** [Plan 001.3 - Summary-First Catalog CLI](001.3-catalog-cli.md)  
**Sequence:** 001.4  
**Created:** 2026-08-20  

## Relationship to Plan 001

Plan 001 established read-only, single-pass directory scanning. Plan 001.3 exposed scans through the CLI. This subplan adds an interactive progress indicator without adding a preliminary traversal, a percentage estimate, or persistent scan state.

## Goal

Show useful live feedback during `archiver catalog scan ROOT` while preserving the scanner's single-pass behavior and keeping non-interactive command output stable.

## Command interface

Extend the scan command with:

```text
archiver catalog scan ROOT [--no-progress]
```

- Progress is enabled by default only when standard error is attached to a terminal.
- `--no-progress` suppresses the indicator in an interactive terminal.
- Non-interactive invocations do not render progress. Their stdout remains the existing final scan summary.
- This subplan deliberately does not pre-count the tree and does not show a percentage. File count, logical bytes hashed, elapsed time, and current relative path are reported as completed work.

## Design decisions

- Add a typed `ScanProgress` value and an optional progress callback to `Catalog.scan_directory()`. Emit it only after a file has been hashed and its observation has been persisted for the in-progress scan.
- Implement a standard-library CLI renderer that writes a throttled, single-line status to stderr. It terminates the line before final success or error output.
- Keep source reads, hashing, persistence transactions, and current-scan promotion unchanged. Progress is ephemeral and requires no schema migration.
- A caller-supplied callback exception remains a scan failure, preserving atomic current-state semantics. The CLI renderer handles terminal-write failures internally by disabling further live updates.
- Excluded directories, including `.archiver`, must not contribute to progress counts or current-path output.

## Validation

Add automated coverage for:

- callback progress counts, logical byte totals, and POSIX relative paths for normal, nested, duplicate, and empty scans;
- control-directory exclusion and source-file immutability;
- callback failure preserving the prior current state;
- interactive stderr rendering, non-interactive suppression, `--no-progress`, and final newline behavior;
- unchanged scan summary, CLI error handling, and deterministic observation results.

Run pytest, Ruff lint, Ruff format check, and mypy. No database schema change is expected.
