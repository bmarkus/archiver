## Relationship to Plan 001

This subplan adds a bounded query over the current successful state of a catalog location. It preserves Plan 001's observational semantics: paths and mtimes are displayed observations, while content identity remains the full SHA-256 digest.

## Goal

Make current catalog contents practical to explore from the CLI without materializing or printing an unbounded file list.

## Command interface

```text
archiver catalog files ROOT [--path GLOB] [--limit N] [--sort path|size|date] [--reverse]
```

- Results default to 20 rows. Explicit larger limits are permitted.
- `--path` matches the full POSIX relative path with a case-sensitive SQLite glob.
- `path` sorts ascending; `size` and observed modification `date` sort descending. `--reverse` inverts the primary sort. Relative path is the deterministic tie-breaker.
- Output is a width-aware terminal table with UTC mtime, human-readable decimal size, a shortened display digest, and a truncated path column.
- The summary reports the total matching file count and total logical size across all matches, not only the displayed rows.

## Implementation record

- Added `CurrentFileSort` and `CurrentFileSearch`, including total-match and total-size metadata.
- Added `Catalog.search_current_files()` with SQLite-side filtering, aggregate counting, ordering, and limiting; it never materializes the catalog-wide current-file list.
- Added `catalog files` output and integration coverage for limits, globs, sorting, current-state safety, compact display units, shortened digests, and terminal-width path truncation.
- No database schema change or migration was required.
