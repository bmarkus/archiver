## Relationship to Plan 001

Plan 001 provides a safe SQLite catalog API. This subplan makes its core lifecycle and duplicate summary available from a command line without introducing archive management, destructive operations, or unbounded catalog dumps.

## Goal

Provide a small, dependency-free `archiver` command for creating and scanning an in-place catalog and inspecting its high-level state.

## Command interface

Add a console entry point backed by the standard-library `argparse` module.

```text
archiver catalog init ROOT
archiver catalog info ROOT
archiver catalog scan ROOT
archiver catalog duplicates ROOT
```

- `init` requires an existing, non-symlink directory, creates `ROOT/.archiver/catalog.sqlite`, and does not perform a scan. It must refuse to overwrite an existing catalog.
- `info` reports the canonical root, catalog UUID, schema version, database path, and most recent successful scan summary. Before a successful scan, it reports that no current state exists.
- `scan` opens the catalog at the fixed in-root path, performs the existing read-only scan of `ROOT`, and prints its completed `ScanSummary`.
- `duplicates` prints an aggregate only: duplicate-group count, total duplicate file instances, and potential redundant bytes. Potential redundant bytes are the sum of `(copy count - 1) * content size` across current duplicate groups. This is descriptive only and must not imply deletion safety.

The first CLI increment deliberately omits raw file listing, duplicate-member paths, scan history listing, filtering, pagination, JSON, and `--all`. Those capabilities can be added later with an explicitly bounded query design.

## Design decisions

- Store one catalog per scanned root at `.archiver/catalog.sqlite`. The CLI exposes only that root as a location in this increment, although the library's existing multi-location data model remains unchanged.
- Exclude the entire `.archiver` control directory from scans, including SQLite sidecars and future internal control files. Scanning must not modify user-owned source files.
- Add narrow typed catalog APIs for the data used by `info` and the aggregate duplicate summary; the CLI must not use raw SQLite queries or private catalog state.
- Use concise, deterministic human-readable output. Successful commands exit `0`; expected operational failures exit `1`; invalid command syntax retains `argparse` exit code `2`. Domain-error messages go to stderr and name the relevant root or catalog path.
- Keep timestamps human-readable in UTC when displayed. Do not add third-party CLI or formatting dependencies.

## Validation

Add CLI-focused tests using temporary directories for:

- console entry point and help output;
- catalog initialization, repeat-initialization refusal, and missing-catalog errors;
- unscanned and scanned `info` output;
- successful scans, nested files, empty directories, and duplicate aggregate calculations;
- exclusion of `.archiver` and its SQLite sidecars from observations;
- scan failure exit handling and preservation of the prior current state;
- deterministic output and exit codes.
