## Scope

Implement Catalog.tags(), TagVocabularyQuery and tag_name/tag_usage vocabulary
from [the final contract](004-public-api-target.md). Operations are where(),
sort(), limit(), provenance(kind); terminals are bounded fetch() and complete
count(). Default bound 20, name ascending. No root parameter.

Reuse current vocabulary SQL semantics: active assertions, distinct content
counts, separate user/system assertion counts, and provenance affecting BOTH
inclusion and all counts. Preserve orphaned content usage. No tag mutations.

Regex uses Python re.search, including inline flags and substring matching.
Validate source strings before SQL at expression construction. Multiple regex
where clauses mean AND. Store semantic regex strings in immutable descriptions;
create needed temporary SQLite function(s) only during terminal execution,
unregister in finally on success/failure. No persistent helper state or global
mutable state. Count and row selection must apply identical regex/scope rules.

Migrate catalog tags available directly to the query. CLI ROOT still selects
the catalog database, not the vocabulary scope. Preserve regex validation
before catalog opening, original regex display, provenance/sort reporting,
reverse direction, totals, output and exit codes.
Remove search_available_tags, AvailableTagSearch, and AvailableTagSort.

## Acceptance tests

- All current vocabulary semantic/CLI tests migrated and preserved.
- Immutable scope/order/limit replacement, regex AND, invalid domain
  predicates, bounds, provenance, and regex validation before any SQL.
- Provenance-restricted content/assertion/user/system metrics with multiple
  producers; orphaned and retracted-only cases.
- Primary ascending/descending sorts and name-ascending ties for count sorts.
- Complete count versus bounded fetch; SQL-side ordering/limits/aggregation.
- Regex helper cleanup on both terminal failures and successes; sequential
  reuse of different queries on one catalog cannot leak filters.
- Read-only source/catalog persistence, close/reopen and closed-catalog errors.
- Direct CLI construction, unchanged outputs/errors, removal of old consumers.
