## Goal and scope

Let callers examine successive ranges of duplicate-content groups without
collecting earlier groups in Python. Add immutable `DuplicateGroupQuery.offset()`
and CLI `catalog duplicates --group-offset`. A row means one duplicate-content
group, not a file instance within that group. This is a new capability following
the completed 004.1–004.8 baseline, not a bug correction or authority change.

Activated and implemented at the user’s subsequent request on 2026-11-07.
The planning outcome below records the earlier preparation checkpoint.
The domain model and invariants remain authoritative; retain historical outcomes.

## API contract

Add `DuplicateGroupQuery.offset(count: int) -> Self` with a default group offset
of zero. Offsets count groups to skip and use zero-based positions:

```python
query = catalog.duplicates(root)
query.offset(10).limit(10).fetch()  # positions [10, 20): displayed groups 11–20
query.offset(90).limit(10).fetch()  # positions [90, 100): displayed groups 91–100
```

- Return a new query; preserve the original. Repeated `offset()` replaces the
  previous offset, and `offset(0)` resets it. Sorting, group limit, and member
  limit retain the offset; setting offset retains those other clauses.
- Validate eagerly without database reads. Accept exact `int` values in
  `0 <= count <= 2**63 - 1` (SQLite's signed-integer parameter range).
  Reject `bool`, floats, strings, and `None` with `TypeError`; negative and
  out-of-range integers raise `ValueError`. Existing positive-limit rules remain.
- Clause semantics are always group/aggregate, order, skip offset groups, then
  apply group limit, regardless of transformation call order. Keep default
  redundant-bytes descending and all existing supported sort expressions.
  Full algorithm/digest ascending breaks primary ties, including descending
  sorts. Members remain full POSIX relative path ascending.
- `fetch()` returns the same bounded `tuple[DuplicateGroupView, ...]` after the
  offset; only selected groups get member previews. `stream()` yields bounded
  handles after that offset. Member limits and complete group metrics do not change.
- `stream_all()` removes only the group limit and **honors the offset**, yielding
  the remaining suffix. Use `offset(0).stream_all()` for the complete population.
  Member streams are unchanged; group offsets never skip member paths.
- `summary()` ignores offset, group limit, member limit, and sorting. It describes
  all duplicate groups in the resolved successful scan, including skipped ones.
- Offset at or beyond the population returns an empty tuple/iterator. A final
  partial page returns its remaining groups. Unknown/unscanned/duplicate-free
  roots keep existing empty results and zero summaries.
- Offset zero preserves all existing results, defaults, types, and lifetimes.
  No `__getitem__`, slicing overload, `page()` wrapper, or new result envelope.

## Refresh and lifetime semantics

A query remains a reusable live description, not a pinned paging session.
`fetch()` resolves the latest successful scan when called; each group stream
resolves it once on first advancement, not when the generator is constructed.
Offset positions apply to that terminal's deterministic ordering in that scan.

If the successful current scan and ordering stay unchanged, adjacent pages
partition the same group sequence without overlaps or omissions. After a refresh,
the next page request uses the new successful scan. Changed group membership,
counts, sizes, or redundant bytes may move groups, so paging across refreshes can
repeat or skip content identities. Group numbers are display positions, never
persistent identities; full `ContentId` remains the group identity. Failed or
interrupted scans do not replace the successful state and cannot shift pages.

A running stream and every handle it yields stay pinned to their resolved scan,
even if a refresh occurs before the next advancement or member read. A retained
handle still reads its old observed members after its outer stream closes.
Fresh terminals from the same query resolve current state again. Preserve open
catalog requirements, independent cursor ownership, and cleanup on exhaustion,
close, and error; use `contextlib.closing` for early exit. Pinning observations
does not pin live filesystem bytes.

The CLI also performs live page requests. Summary and row fetch remain separate
terminals as in 004.8: they do not promise one atomic snapshot under a concurrent
refresh. Range numbers derive from the requested offset and actual returned rows;
the printed complete summary total can reflect a different successful scan.
Do not introduce hidden transactions, locks, public scan selectors, paging tokens,
or snapshot sessions. Document that reviewing one unchanged scan across pages
requires avoiding successful refreshes during that review. Explicit historical
scan selection or persistent review sessions would require a separate plan.

## CLI contract

Add only `--group-offset N` to `catalog duplicates`, default zero, accepting the
same nonnegative signed-integer range as the API. Invalid values use argparse
exit code 2 before opening a catalog. Pass it through the public duplicate query;
keep SQL, private descriptions, and connections out of CLI code.

```powershell
uv run archiver catalog duplicates ROOT --details --group-offset 10 --group-limit 10
uv run archiver catalog duplicates ROOT --details --group-offset 90 --group-limit 10
```

- Keep existing group/member defaults of 20 and summary-first output.
  `--member-limit` continues to bound each selected group's member preview.
- With offset zero (omitted or explicit), preserve existing output verbatim,
  including group numbering and the existing showing-first/all footer.
- With nonzero offset and returned rows, number the GROUP column from `offset + 1`.
  Print `Showing groups A-B of T duplicate groups.`, where A is offset + 1,
  B is offset + returned count, and T is the complete summary group count.
  These are one-based inclusive display positions; API offsets remain zero-based.
- With nonzero offset and an empty page, retain the complete summary and print
  `No duplicate groups in the requested page (offset N).` Do not print a reversed
  or fabricated range or claim that the full population is empty.
- No-current-scan output remains `Current scan: none`. With no `--details`,
  accept/validate the flag but display only the unchanged complete summary,
  matching the existing group/member limit behavior in summary-only mode.
- Keep existing primary ordering, full identities, digest abbreviation, source
  safety, runtime-error exit codes, and member display unchanged. No CLI sort,
  member offset, unbounded output, interactive shell, or saved cursor is added.

## Implementation boundary

Extend the existing immutable public query and private duplicate descriptions,
compilers, and executors with group-offset data only where selection needs it.
Apply parameterized SQL `OFFSET` after deterministic ordering and with the
applicable limit. For an unbounded suffix, use SQLite's supported unbounded-limit
form with a bound offset. Summary compilation must omit pagination entirely.
Do not slice a fetched population, use `islice` to consume skipped groups, or
materialize members for skipped groups. This bounds returned Python objects;
SQL may still aggregate/order/traverse earlier groups. No performance guarantee
for deep offsets, indexing project, keyset pagination, or benchmark is included.
No schema/version or dependency changes are expected.

## Acceptance tests

Use temporary synthetic roots, explicit order/ties, and deterministic refresh
hooks rather than timing or directory enumeration assumptions.

1. Validate zero, positive, reset, repeated replacement, integer maximum,
   negative/overflow, bool, float, string, and None offsets. Prove immutability,
   eager validation, and no catalog reads during transformations.
2. On at least 100 duplicate groups, verify exact identities at positions
   `[10, 20)` and `[90, 100)`, adjacent pages without overlap for unchanged state,
   final partial pages, offset equal to count, and offsets beyond count.
   Include nested paths, duplicate empty files, all supported sort fields in
   both directions, and tied metrics with full-identity tie-breakers.
3. Verify order/offset/limit call-order equivalence, repeated clauses, independent
   member bounds, complete per-group metrics, and summary invariance under pages.
4. Check fetch versus bounded stream parity; `stream_all()` returns the suffix
   despite a smaller group limit; reset to zero recovers all groups. Instrument
   SQL/row materialization to prove offset is SQL-side and skipped groups/members
   are not materialized in Python. Retain cursor cleanup and closed-catalog tests.
5. Deterministically refresh between page requests with an earlier group inserted
   or removed, and assert new pages match the new scan's sorted sequence. Show
   the documented possibility of repeats/skips. A stream created before refresh
   but first advanced afterward sees the new scan. A started stream and retained
   handles keep old scan membership through refresh and outer-stream closure.
6. Verify failed/interrupted refresh isolation, unknown/unscanned/empty roots,
   close/reopen persistence, and unchanged source bytes/mtime/mode and catalog
   data/schema/history on successful and failing read paths.
7. Exercise CLI default/explicit-zero compatibility, middle/last/partial/empty
   pages, absolute group numbering, complete totals, member bounds, no-scan state,
   summary-only flag behavior, help/defaults, malformed input before catalog open,
   and existing error/width contracts. Controlled refreshes must not imply a
   shared snapshot between summary and fetch; unchanged-state tests assert exact
   ranges/totals. Existing CLI/API semantic coverage must remain passing.

## Implementation outcome — 2026-11-07

Implemented immutable duplicate group offsets end to end. Public queries carry
validated `group_offset`, the existing private description carries it to SQL,
and group selection applies parameterized `LIMIT ? OFFSET ?`. Unbounded suffixes
bind limit -1; offset zero retains the prior SQL path. Summary and member SQL
remain independent of group pagination. No alternate query engine or Python
population slicing was introduced.
