## Goal

Add an end-to-end, bounded catalog-wide view of the active tag vocabulary: a typed usage query and the new `catalog tags available` CLI command.

## Vocabulary semantics

- Include a canonical tag name only when it has at least one active assertion anywhere in the catalog.
- Tagged content remains represented when it has no current path. Vocabulary membership and counts do not depend on current scans.
- Exclude names whose assertions are all retracted.
- A provenance filter controls both inclusion and every reported count. Without a filter, counts include all active user and system assertions.
- Distinct-content count counts a content identity once per tag even when several active provenance sources assert that tag.
- Assertion, user, and system counts count active assertion rows.
- Optional regex filtering uses Python `re.search` over the complete canonical tag name. Matching is case-sensitive unless the expression supplies an inline flag such as `(?i)`.
- The public API accepts a regex source string, not a compiled pattern. Compile and validate it at the start of the query method, before issuing SQL. An invalid expression raises `re.error`, issues no SQL from the query method, and does not mutate catalog state.

## Public API

Add explicit immutable result types with the semantic equivalent of:

- `TagUsage`, containing `tag`, `content_count`, `assertion_count`, `user_assertion_count`, and `system_assertion_count`.
- `AvailableTagSearch`, containing bounded `tags` rows and `total_matches`, the complete number of matching active tag names.

Add a new catalog-wide `Catalog` query with the semantic equivalent of:

```python
search_available_tags(
    *,
    name_regex: str | None = None,
    provenance: TagProvenanceKind | None = None,
    sort_by: AvailableTagSort = "name",
    reverse: bool = False,
    limit: int = 20,
)
```

`AvailableTagSort` supports `name`, `content`, and `assertions`. `limit` must be positive, and provenance must be `user`, `system`, or `None`. Name defaults ascending; content and assertions default descending. Reverse inverts only the primary direction. For content and assertion sorts, canonical tag name remains the ascending deterministic tie-breaker. For name sorting, the name is the primary key, so reverse produces descending names and there is no separate tie-breaker.

The API is catalog-wide and therefore takes no location/root argument. The CLI `ROOT` identifies the in-root catalog database, not a vocabulary scope.

## Query shape and regex integration

- Aggregate only active assertion rows, applying provenance before inclusion and counts.
- Compute the complete matching-tag total before applying the result limit.
- Apply ordering and limit in SQLite before usage rows are materialized.
- When a regex is supplied, compile it before the first SQL statement. Register a connection-local SQLite function bound to that compiled expression only for the duration of the query, use it to preserve Python `re.search` semantics while applying the row limit in SQLite, and unregister it in `finally` so no helper state remains on the connection after success or failure.
- Do not persist helper state, add tables or indexes, or change schema version 2.

## CLI

Add:

```text
archiver catalog tags available ROOT
    [--regex REGEX]
    [--provenance user|system]
    [--limit N]
    [--sort name|content|assertions]
    [--reverse]
```

- Default to 20 rows sorted by name ascending.
- Render `Tag`, `Content`, `Assertions`, `User`, and `System` columns with deterministic alignment.
- Report the complete matching-tag count and whether all or only the first bounded rows are shown.
- Always report the effective sort and direction and the effective provenance (`all`, `user`, or `system`). When a regex is supplied, report its original source string.
- Validate `--regex` during argument parsing while retaining its original source string. Reject an invalid expression as a clear CLI usage error before resolving the catalog path, opening the catalog, or issuing SQL.
- Use the shared standard-library display conventions without introducing color or a third-party table dependency.
