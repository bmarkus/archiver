# Plan 003.3b — Tag-Aware Current-File Search

**Status:** Planned
**Parent plan:** [Plan 003.3 — Bounded Tag and File Search](003.3-bounded-tag-and-file-search.md)
**Depends on:** [Plan 003.3a — Multi-Tag Content Search](003.3a-bounded-tag-query-apis.md), [Plan 001.5 — Bounded Current-File Browsing](001.5-bounded-current-file-browsing.md)

**Created:** 2026-08-24

## Goal

Add an end-to-end tag-aware current-file search: a typed bounded catalog API and compatible extensions to `catalog files`. Tag filters compose with the existing path GLOB and current-file sorting while the legacy command path remains byte-for-byte compatible when no tag-aware option is used.

## Matching semantics

- One result row represents one current path from the requested root's latest successful scan.
- Optional tag filters use the multi-tag `all|any`, provenance, deduplication, and active-assertion semantics established in Plan 003.3a.
- Tag filters apply to the content identity observed at each current path. Duplicate paths with the same content therefore share the same displayed tags but remain separate file rows.
- The optional path filter remains the existing case-sensitive SQLite GLOB over the complete POSIX relative path. Do not add path regex behavior.
- The provenance filter affects requested-tag matching only. Displayed tags are all distinct active tag names on the content, regardless of provenance.
- Results preserve current-scan isolation after refresh or failed/interrupted scans.

## Public API

Add explicit immutable result types with the semantic equivalent of:

- A current-file-with-tags row containing the existing `FileObservation`, complete distinct active-tag count for its content, and bounded alphabetical active-tag names.
- A tag-aware current-file search result containing bounded rows, complete matching-file count, and complete logical size across every matching current path.

Add a new `Catalog` query with the semantic equivalent of:

```python
search_current_files_with_tags(
    root,
    *,
    path_glob=None,
    tags=(),
    match="all",
    provenance=None,
    sort_by="path",
    reverse=False,
    limit=20,
    tag_limit=3,
)
```

An empty tag sequence is valid so callers can request displayed tags without filtering. Provenance is invalid without at least one requested tag. Numeric limits must be positive; a distinct all-tags mode may materialize every distinct active tag only for already bounded file rows.

Preserve `Catalog.search_current_files()` and `CurrentFileSearch` unchanged.

## Query shape and bounds

- Compose current location, latest successful scan, optional path GLOB, and optional matching-content predicate before totals, ordering, and limiting are applied.
- Preserve the existing defaults: path ascending; size and observed modification date descending; reverse inverts the primary direction; relative path is the deterministic tie-breaker.
- Compute complete file and logical-size totals before the row limit.
- Apply the file-row limit in SQLite before creating observations or fetching tag previews.
- Fetch tag previews only for distinct content IDs present in the bounded file rows. Duplicate file rows may reuse the same bounded preview in memory.
- Do not change schema version 2.

## CLI

Extend:

```text
archiver catalog files ROOT
    [--path GLOB]
    [--tag TAG]...
    [--match-any-tag]
    [--provenance user|system]
    [--show-tags]
    [--display-tag-limit N | --all-tags]
    [--limit N] [--sort path|size|date] [--reverse]
```

- Repeating `--tag` uses AND semantics by default. `--match-any-tag` changes the requested-tag filters to OR and requires at least one `--tag`.
- `--provenance` requires at least one `--tag`.
- A tag filter, `--show-tags`, `--display-tag-limit`, or `--all-tags` enables the tag-aware table. With none of those options, dispatch through the existing query and renderer so output remains exactly compatible.
- Tag display defaults to 3 distinct alphabetical names. Numeric display limits and `--all-tags` are mutually exclusive.
- The tag-aware table has `Modified (UTC)`, `Size`, `SHA-256`, `Path`, and `Tags` columns.
- Allocate bounded width to tags and truncate the path column before dropping or truncating tag names. Use a stable fallback width when no interactive terminal width is available.
- `--all-tags` may add continuation lines beneath a file row. Do not add color or a generic third-party table framework.
- Preserve complete matched-file and logical-size totals below bounded rows and report the effective requested-tag expression when filters are present.

## Validation

Add automated coverage for:

- AND/OR tags, deduplication, provenance filtering, retracted assertions, and invalid cross-option combinations;
- composition with path GLOB, all existing sort modes, reverse order, and deterministic ties;
- current-scan isolation after successful, failed, and interrupted scans;
- duplicate current paths sharing tag previews while remaining separate rows;
- complete file and logical-size totals under row and tag-preview limits;
- zero-tag display-only searches and files whose content has no active tags;
- alphabetical previews, `+N` overflow, all-tags continuation wrapping, empty results, and narrow/fallback terminal widths;
- positive row/tag limits and limits being applied before observations or tag rows are materialized;
- exact output and behavior compatibility for `catalog files` when no tag-aware option is supplied;
- `Catalog.search_current_files()` and `CurrentFileSearch` remaining unchanged;
- source bytes and metadata, scan history, assertions, retractions, and schema version remaining unchanged on success and failure.
