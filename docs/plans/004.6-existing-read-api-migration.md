## Shared implementation guidance

- Keep the existing duplicate handles, independent cursors, scan pinning, and
  mixed bounded/unbounded streams passing throughout the migration. This work
  does not extend streaming to content, vocabulary, or detail views.
- Resolve observation scope once per multi-statement terminal. Separate CLI
  totals and fetch calls remain separate terminals and need not share a
  snapshot; tag assertions also have no cross-statement snapshot guarantee.
- Reuse focused SQL/materialization helpers only where semantics match. Allow
  simple per-selected-content preview queries; do not turn this into batching,
  indexing, schema, or performance work. Bounds constrain returned Python
  objects, not total SQLite aggregation/sorting work.
- Migrate CLI parsing to typed expressions without changing displayed request
  order, sort defaults, or error timing. Keep parser-only aliases local once
  their last public signature is removed. Never recreate search envelopes.
- Preserve semantic regression tests, and use deterministic instrumentation
  for scan changes, cursor cleanup, and SQL bounds instead of timing tests.
- Each child inventories runtime callers, exports, tests, and live API docs.
  Record deferred notebook corrections without making them an acceptance gate.
