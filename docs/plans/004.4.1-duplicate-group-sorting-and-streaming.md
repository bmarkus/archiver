## Goal

Actual archive exploration requires sorting duplicate groups and processing
every group and every member without collecting either entire population in
Python memory. Extend the existing grammar to support this demonstrated need
and provide a read interface for later duplicate-handling workflows.

This is a dated extension of 004.4, not a correction of its implementation.
It supersedes only the prohibitions on configurable duplicate ordering and
explicit unbounded group/member streaming. Preserve historical outcomes.

## Typed sorting

Add immutable `DuplicateGroupQuery.sort(expression)` with these public factories
from `archiver.query`, each supporting `asc()` and `desc()`:

- `size`: content size in bytes (reuse the existing expression).
- `duplicate.file_count`: complete file-instance count.
- `duplicate.redundant_bytes`: complete `(file_count - 1) * size_bytes`.

Keep redundant bytes descending as the default. Every primary ordering appends
full content algorithm and digest ascending, including descending primary sorts.
Member ordering remains full relative POSIX path ascending. Repeated `sort()`
replaces ordering; transformation order relative to limits does not affect
semantics. Validate eagerly, rejecting strings, callbacks, and expressions from
other domains such as path, mtime, and tag usage. File queries reject the new
duplicate-specific expressions. No configurable identity sort is needed here.

## Bounded and unbounded terminals

Existing group and member limits remain exact positive integers, defaulting to
20, with immutable replacement and existing type/value errors. Omitting
`member_limit()` means 20, never unlimited.

| Terminal | Result | Group bound | Member bound |
| --- | --- | --- | --- |
| `query.fetch()` | `tuple[DuplicateGroupView, ...]` | query limit | member limit; existing tuple preview |
| `query.stream()` | `Iterator[DuplicateGroupHandle]` | query limit | members loaded only on request |
| `query.stream_all()` | `Iterator[DuplicateGroupHandle]` | none; ignores query limit | members loaded only on request |
| `handle.stream_members()` | `Iterator[FileObservation]` | one selected group | inherited member limit |
| `handle.stream_all_members()` | `Iterator[FileObservation]` | one selected group | none; ignores member limit |

`summary()` continues to return complete metrics independent of sorting and both
limits. `fetch()` keeps its result type, bounded materialization, and default
behavior; a caller may select its ordering using the new `sort()`.

The immutable `DuplicateGroupHandle`, defined in `archiver.query` and re-exported
from `archiver`, exposes `content_id`, `size_bytes`, `file_instance_count`, and
`potential_redundant_bytes`. These metrics are complete regardless of bounds.
It has no eager `members` tuple. Private state retains the catalog, location,
resolved scan, exact content identity, and member bound. Keep SQL identifiers
out of its public construction contract; no general query-backed object layer.

```python
from archiver.query import duplicate, size

query = catalog.duplicates(root).sort(size.desc()).limit(2).member_limit(3)
for group in query.stream():                # At most 2 groups
    for member in group.stream_members():  # At most 3 members per group
        print(member.relative_path)

for group in query.stream_all():                # Every duplicate group
    for member in group.stream_all_members():  # Every member, incrementally
        print(group.content_id, member.relative_path)

# Bounds are independent: selected groups can have all their members streamed.
for group in query.sort(duplicate.file_count.desc()).stream():
    for member in group.stream_all_members():
        print(member.relative_path)
```

This naming refines the initial discussion's unbounded `stream_members()`:
ordinary stream calls are bounded at both levels; names containing `all`
explicitly remove only the corresponding level's bound. No `fetch_all()`,
unlimited member tuples, or overloaded `None` limits are introduced.

## Laziness, scan consistency, and resources

Construction and transformations perform no reads beyond existing root
validation. At first advancement, each group iterator resolves the latest
successful scan exactly once. All handles and their member iterators use that
scan, even after a refresh or after the outer iterator has closed. A retained
handle may open fresh member iterators while its catalog remains open; it must
not silently re-resolve current state. Distinct terminals may select different
scans. This pins observed membership, not live filesystem contents.

Group iteration does not fetch members. Each member iterator opens its own
cursor on first advancement. Interleaved group/member iterators must work
without sharing cursor position. Unknown, unscanned, and duplicate-free roots
yield nothing and retain existing zero-summary behavior; empty-file duplicates
remain valid groups. Closed-catalog use must fail consistently with existing
query errors, including after partial iteration.

Return generator-backed iterators with `close()` support. Close each cursor
in `finally` on exhaustion, explicit closure, and iteration errors. Closing an
outer stream does not close independently opened member streams. A plain
`break` does not guarantee closure: document `contextlib.closing` for partial
consumption and close member and group iterators before closing the catalog.

## Compilation and memory contract

Extend existing private descriptions, compiler, and execution helpers. Keep
one grouped SQL selection path and one member path with an explicit bound or
unbounded execution option; bounded fetch may materialize the bounded iterator.
Compute grouping, complete metrics, ordering, and applicable limits in SQLite.
Use closed expression mappings and bound values. Do not use OFFSET pagination,
Python sorting, all-group `fetchall()`, or all-member buffering in either stream.
Bounded fetch may retain bounded collections.

Each stream materializes one row/handle at a time (or a small fixed batch), with
Python working memory independent of total groups and files unless the caller
retains results. SQLite may aggregate and sort the complete relation before
yielding: no guarantee of constant database-engine memory or immediate first
result. Member expansion may issue one query per consumed group; optimization
requires evidence and must not change semantics.

## Scope and future workflows

Preserve byte identity, root scope, latest-successful-scan isolation, foreign
keys, source/catalog read-only behavior, and schema version 2. No schema,
dependency, CLI options/output, mutation, duplicate keeper policy, deletion,
ingest, or filesystem authority change. No arbitrary grouping, new predicates,
async API, cache, general snapshot API, or restoration of retired facades.

Later plans can use the streams to inspect candidate actions. Before acting on
files they must separately define authority, stale-observation validation, and
failure recovery. A streamed observation is not permission or proof that the
current bytes still match. Do not implement those workflows in this plan.

## Acceptance tests and completion

- Sorting in both directions by each field, deterministic full-identity ties,
  replacement semantics, immutability, and invalid/cross-domain expressions.
- Unchanged default fetch, bounded SQL group/member selection, and complete
  summary/group metrics despite display limits or sorting.
- More than 20 groups and a group with more than 20 members: both defaults stay
  bounded, each explicit all-terminal ignores only its own bound, and every
  member appears exactly once in deterministic order.
- Independent mixed bounds, nested paths, duplicate bytes, empty-file groups,
  and empty/unknown/unscanned roots.
- Instrumented lazy execution: no member query before member consumption; the
  first yield does not materialize later groups or an entire large member set.
  Assert SQL-side bounds/no bound as appropriate without timing thresholds.
- Scan pinned across refresh, retained handles after outer exhaustion/closure,
  lazy query reuse, and failed/interrupted scan isolation.
- Partial consumption, explicit closure, iterator errors, closed catalogs,
  and interleaved member/group cursors, with observable resource cleanup.
- Read-only success/failure assertions for source bytes/metadata and catalog
  data, schema, history, and current state; existing CLI regressions pass.
- Executable public notebook verifies bounded and complete processing.
