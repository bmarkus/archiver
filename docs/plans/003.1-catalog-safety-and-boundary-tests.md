## Goal

Add regression coverage for transactional failure, malformed persistence, filesystem boundaries, hashing races, location isolation, refresh snapshots, and CLI initialization safety. This is a test-only increment: it adds no production API, CLI, or schema behavior.

## Coverage added

- Refresh application rolls back all rows after a late SQLite insertion failure or contradictory content size, and stale applications write no rows.
- Recursive scans ignore directory symlinks; location-scoped current state and duplicates remain isolated across roots.
- Hashing remains bounded and rejects invalid chunk sizes and detectable path/handle mutations.
- Invalid or malformed catalogs are rejected cleanly; historical running and failed rows cannot become current state.
- A refresh applies its captured filesystem observation, while a later reconciliation detects subsequent source mutation.
- CLI initialization rejects non-directory roots and unsafe control-directory paths without changing sources.

## Non-goals

- No production code, public type, CLI, or SQLite schema changes.
- No retry, repair, crash-recovery, or archive-management behavior.
- No changes to the documented reconciliation baseline semantics.
