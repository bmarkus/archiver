## Scope

Implement Catalog.contents(), ContentQuery, ContentRecord, ContentDetailQuery
and with_details(root=..., path_limit=20, tag_limit=3, all_tags=False) following
[the final contract](004-public-api-target.md). Reuse content/tag predicates
from 004.5 and active-tag preview materialization from 004.6a.

Base fetch has 20-row default and fixed full identity ascending ordering.
count() counts all matching identities. Detail fetch preserves those parents
and adds root-scoped path count/previews and all-provenance active tag
count/previews. current_path_count() on the detail query counts paths over
ALL matching identities at that root, not just selected parents.
No public configurable content ordering, streaming, or additional reductions.

Root scope affects only paths. Matching is catalog-wide, including identities
with no current occurrence anywhere. An unknown/unscanned root yields matching
content details with zero paths. Resolve its current scan once per terminal.
Bound parents before path/tag rows; no catalog-wide Python aggregation.

Migrate catalog tags find to this query and typed detail renderer. Preserve its
requested-tag expression, options, total content/path counts, truncated tag
display, all-tags wrapping, details bounds, empty states, and exit behavior.
Remove search_tagged_content, search_content_by_tags, TaggedContent,
TaggedContentSearch, and MultiTagContentSearch. Former single-tag consumers
requiring assertion provenance use retained tags_for_content(id) explicitly.

## Implementation notes from the current baseline

Start from the content table, not the active-assertion relation used by the
old searches. Reuse _compile_active_tag_match for predicates and the 004.6a
preview helper for display; keep selection, path scope, and displayed tags
independent. ContentRecord belongs with frozen domain records in models.py,
re-exported from archiver; public query classes belong in archiver.query.
Retain ContentTagView's existing fields.

Use one resolved successful scan for all path statements in each fetch or
current_path_count terminal. A missing scan is an empty path scope, not an
empty content result. Validate/canonicalize root at with_details construction;
even an empty/unknown-root terminal must check that its catalog is open.

search_tagged_content formerly returned only assertions for the requested tag
and provenance. tags_for_content returns all active assertions: migrated callers
that need the former subset must explicitly filter by tag and provenance,
preserving producer identity and ordering. Detail tag-name previews are not a
replacement for assertion records. Cover this in migrated automated tests.

Retire public TagMatchMode here when its final search signature disappears;
keep any CLI-only literal local. Translate tag_limit=None to all_tags=True
and preserve CLI requested-tag order. The 003.2 and 003.3a tutorial updates
may be deferred.

## Acceptance tests

- Base all-content query includes untagged/orphaned content; tag predicates
  include orphaned matches and exclude retracted-only matches.
- Full identity ordering and grouping, including duplicate current paths,
  nested paths, empty files, historical-only content, and multiple locations.
- All/any/provenance semantics identical to file queries; no producer fan-out.
- Complete content/path totals independent of row/path/tag bounds; unknown
  root does not erase matching catalog-wide content.
- SQL-side bounds and reductions; selected parent IDs alone drive previews;
  root scan pinned across member statements, catalog open/close/reopen.
- Read-only success/failure for source metadata, assertions/history/schema.
- CLI output compatibility and direct grammar construction.
- Runtime callers and tests migrate; obsolete types/exports disappear.
  Old notebook callers do not block removal.
- Content queries reject path, duplicate, and vocabulary predicates; exact
  unknown content produces an empty search while retained exact lookups keep
  their existing errors. Base/view creation performs no database reads.
