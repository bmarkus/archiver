## Goal

Add minimal provenance-aware tags to cataloged content. Tags describe SHA-256 content identity rather than a pathname, remain available when no current path refers to the content, and never authorize modification of source files.

The increment exposes current tag operations while retaining assertion and retraction records for future history and merge work. It does not define catalog-merge, conflict-resolution, or effective-tag precedence policy.

## Domain semantics

- A tag belongs to one content identity. Tagging through any current path resolves that path to its content and therefore exposes the tag through every duplicate path.
- A tag assertion records `user` or `system` provenance, source/tool name, source/tool version, an optional stable method/configuration identifier, assertion time, and optional retraction time.
- System producers must provide a non-empty tool name and version. A changed tool version is a distinct provenance source and must not overwrite an earlier assertion.
- User CLI assertions identify `archiver-cli` and its installed package version as their source.
- More than one active provenance source may assert the same tag for the same content. Current tag queries retain each source rather than collapsing away provenance.
- Adding the same content/tag/exact-provenance assertion repeatedly is idempotent. Re-adding it after retraction creates a new assertion.
- CLI removal retracts all active `user` assertions for the selected content and tag. It does not retract `system` assertions. The library can retract an exact provenance source for future system workflows.
- Retraction preserves the assertion row. Public historical-event queries and merge semantics remain future work.

## Persistence and migration

Advance the SQLite schema from version 1 to version 2.

- Add a `tags` table with a unique canonical name.
- Add a content-tag assertion table referencing `content` and `tags`, with provenance kind, source name, source version, source detail, assertion timestamp, and nullable retraction timestamp.
- Use a partial unique index over content, tag, and the complete provenance identity for active rows. Add indexes needed for current content-tag and reverse-tag queries.
- Tag names must match `[a-z0-9][a-z0-9._:-]{0,63}`. No implicit case conversion is performed; invalid names fail clearly.
- Provide an explicit transactional v1-to-v2 migration. `Catalog.open()` must not migrate silently; opening a v1 catalog reports that migration is required.
- Add `archiver catalog migrate ROOT`. Migration preserves the catalog UUID and all existing locations, scans, content, observations, and current-state references. A failed migration rolls back both schema additions and the version update.
- Newly created catalogs use schema version 2. Unsupported, newer, or malformed schemas continue to fail clearly.

## Public API

Add typed values for tag provenance, active content-tag assertions, and bounded reverse-search results.

Provide the semantic equivalent of:

- add a tag by `ContentId` and exact provenance;
- retract a tag by `ContentId`, either for an exact provenance or all user provenance;
- add or retract a user tag through `(root, relative_path)` resolved against the latest successful scan;
- list active assertions by content identity or current path, ordered by tag then complete provenance identity;
- search distinct content identities by tag with an optional `user|system` filter and a positive limit, returning complete match count plus bounded deterministic results.

Unknown content, a path absent from current state, invalid relative paths, invalid tags, invalid provenance, and non-positive limits raise clear domain or value errors. A direct content-ID operation remains available after every path disappears because content records are historical catalog data.

## CLI

Add:

```text
archiver catalog migrate ROOT
archiver catalog tags add ROOT TAG (--path PATH | --content SHA256)
archiver catalog tags remove ROOT TAG (--path PATH | --content SHA256)
archiver catalog tags list ROOT (--path PATH | --content SHA256)
archiver catalog tags find ROOT TAG [--provenance user|system] [--limit N]
```

- `PATH` is an exact POSIX relative path in the current successful scan. Absolute paths and parent traversal are rejected.
- `SHA256` is the canonical 64-character lowercase digest; SHA-256 remains the only content algorithm.
- CLI add/remove operations are user operations. List and find output show provenance kind, source/tool name, version, and optional source detail.
- Reverse lookup defaults to 20 distinct content identities, reports the complete match count, and orders by full content digest.
- Successful idempotent add/remove commands return exit code 0 and state that no catalog change was needed.

## Automatic tags and non-goals

Do not automatically derive `picture`, `text`, `audio`, or other file-kind tags in this increment. Extension-based classification is path-dependent and can conflict for duplicate content; deterministic byte-based classification requires a separate design.

Also exclude tag merge/conflict policy, actor identity, tag renaming, vocabulary administration, bulk tagging, pandas adapters, source-file metadata writes, archive ingest, keeper selection, quarantine, and destructive deduplication.
