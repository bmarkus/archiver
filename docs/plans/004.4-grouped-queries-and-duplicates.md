## Goal

Extension approved 2026-09-29: [004.4.1](004.4.1-duplicate-group-sorting-and-streaming.md)
adds typed sorting and explicit bounded/unbounded group and member streaming.
It supersedes this plan's restrictions on those capabilities prospectively;
the original contract and implementation outcome below remain historical.

Introduce the first grain-changing query domain: duplicate-content groups over
one root's current successful state. Express existing duplicate inspection
through the query grammar without changing what a duplicate means or creating
a parallel duplicate-query engine.

A duplicate group represents one full content identity with more than one
current file instance at the requested root. It is observational only; it does
not nominate a keeper or authorize filesystem changes.

## Public API

Add a lazy immutable constructor and grouped-query type:

```python
query = catalog.duplicates(root)
result = query.limit(20).member_limit(20).fetch()
summary = query.summary()
```

`Catalog.duplicates(root) -> DuplicateGroupQuery` validates and canonicalizes
the root when constructed but resolves the persisted location and latest
successful scan only when a terminal executes. Here, an unknown root means an
existing valid directory that has no catalog location; a nonexistent,
non-directory, or symbolic-link root retains the existing validation failure.
Terminals require the catalog to remain open.

`DuplicateGroupQuery` is defined in `archiver.query` and re-exported from
`archiver`, matching `CurrentFileQuery`.

`DuplicateGroupQuery` exposes only:

```python
query.limit(count)
query.member_limit(count)
query.fetch()
query.summary()
```

New queries default to a 20-group bound and a 20-member-per-group bound.
`limit()` replaces the positive group bound; `member_limit()` replaces the
positive per-group member bound. Both accept only exact `int` values of at
least one; booleans, floats, and strings are rejected. Both transformations
are immutable. `fetch()` returns `tuple[DuplicateGroupView, ...]`; `summary()`
returns the complete `DuplicateSummary` for every matching duplicate group,
independent of either display bound.

No configurable public duplicate ordering is introduced. Existing ordering is
the demonstrated behavior and remains the grouped-query meaning:

- groups: potential redundant bytes descending, then complete content
  algorithm and digest ascending;
- members: full relative POSIX path ascending.

The fixed order deliberately avoids a new sort vocabulary without an existing
use case. A later approved subplan may add typed group ordering if behavior
requires it.

## Group semantics

For every group:

- group by the full persisted content identity, never by filename or path;
- include it only when its current file-instance count exceeds one;
- retain `DuplicateGroupView` fields: full content identity, content size,
  complete file-instance count, complete potential redundant bytes, and a
  bounded member tuple;
- compute potential redundant bytes as `(file_instance_count - 1) *
  size_bytes`; and
- preserve empty-file groups, whose redundant-byte value is zero.

`DuplicateSummary` retains its existing complete metrics: duplicate-group
count, duplicate-file-instance count, and potential redundant bytes. Unknown,
unscanned, or duplicate-free roots yield an empty group tuple and an all-zero
summary. Separate terminals need not share a snapshot if current state changes
between executions. Each terminal resolves one current scan ID at its start. A
multi-statement `fetch()` uses that same scan ID for group selection and every
member expansion, so one result cannot mix observations from different scans.

## Phase 1 API retirement and CLI migration

Remove the superseded `Catalog.duplicate_groups()`,
`Catalog.search_duplicate_groups()`, and `Catalog.duplicate_summary()` methods.
Also remove the now-redundant `DuplicateGroupSearch` composite result and the
tuple-oriented `archiver.pandas.duplicate_groups_frame()` adapter. Their
unbounded or specialized result shapes add no domain capability beyond
`Catalog.duplicates(root).fetch()` and `.summary()` and would leave two public
ways to express the same query.

The project is pre-1.0 and the complete Phase 1 endpoint remains available on
its frozen branch, so these removals are explicitly approved without a
deprecation period. Update the playground and tests to use the bounded grouped
query. Do not add compatibility wrappers or a public or private unbounded
replacement. A grouped-result DataFrame adapter may be designed later if an
actual consumer requires one.

Map the existing duplicate CLI directly to the new public query in this
subplan: construct the query with its requested group and member limits, use
`summary()` for aggregate output, and use `fetch()` for details. Preserve its
arguments, bounds, ordering, empty-state behavior, human-readable output, and
exit behavior. Plan 004.8 remains responsible for mapping the other CLI read
operations.

## Internal design

Add only the private query description, compiler, and execution support needed
for this grouped domain:

- represent a persisted location, the terminal's resolved current scan ID, and
  immutable group/member bounds with domain semantics rather than SQL
  artifacts;
- centralize compilation of the current-scan observation relation and reuse it
  for group selection, summary aggregation, and member expansion;
- calculate complete group metrics in SQLite before applying the group limit;
- apply group and member limits in SQLite before materializing their respective
  rows;
- materialize `DuplicateGroupView`, `DuplicateSummary`, and member
  `FileObservation` values through narrow shared functions; and
- use parameterized SQL and closed internal mappings only.

A bounded group query may use one group statement followed by bounded member
statements for the selected groups. It must not materialize all current
observations or all members to derive bounded results. Do not introduce a
private unbounded mode, legacy group ordering, a general aggregation framework,
arbitrary group keys, projection, snapshots, caching, async execution, another
backend, or a schema change.

## Compatibility and safety

Preserve byte-based content identity, path-scoped file observations,
latest-successful-scan isolation, deterministic output, schema version, and
read-only behavior on successful and failing query paths. Preserve existing
current-file, history, tag, refresh, duplicate CLI, and mutation behavior. The
only approved public removals are the three superseded duplicate catalog
methods, `DuplicateGroupSearch`, and `duplicate_groups_frame()`.

Exclude duplicate resolution, keeper selection, deletion, archive authority,
merge policy, tags, historical grouped queries, arbitrary aggregations,
content/path predicates, public unbounded grouped collection, and any other
public API removal or deprecation.

## Acceptance criteria

- `Catalog.duplicates(root)` provides an immutable, lazy, bounded grouped
  query with complete summary metrics.
- Groups are derived from current observations by full content identity and
  retain existing duplicate definitions, aggregate values, and deterministic
  ordering.
- Group and member bounds apply in SQLite before their rows materialize;
  summaries remain complete and are computed in SQLite.
- The Phase 1 duplicate catalog methods, `DuplicateGroupSearch`, and
  `duplicate_groups_frame()` are removed; their in-repository consumers use the
  bounded grouped query, and no compatibility or unbounded grouped path
  replaces them.
- The duplicate CLI constructs the grouped query directly while preserving its
  existing interface and output.
- No source/catalog mutation, schema change, duplicate resolution, public
  unbounded grouped collection, tag behavior, or historical grouping is
  introduced.
- Required validation passes and the implementation outcome is recorded here.

## Implementation outcome

- Added the public immutable `DuplicateGroupQuery`, available from
  `Catalog.duplicates(root)`, `archiver.query`, and the top-level `archiver`
  package. Its group and member bounds default to 20, replace immutably, and
  reject non-integer or non-positive values.
- Added one internal duplicate-group description and SQLite compiler/executor
  path. Each terminal resolves a persisted location and current scan once;
  bounded group selection, member expansion, and complete summary aggregation
  execute in SQLite with parameterized bounds and deterministic ordering.
- Pinned every group and member statement within one `fetch()` to the same scan
  ID without introducing a snapshot, transaction API, cache, schema change, or
  unbounded grouped mode.
- Migrated the duplicate CLI directly to `duplicates().summary()` and bounded
  `duplicates().fetch()` while preserving its command arguments and output.
- Removed `duplicate_groups()`, `search_duplicate_groups()`,
  `duplicate_summary()`, `DuplicateGroupSearch`, and
  `duplicate_groups_frame()` as approved. Updated the playground and existing
  tests to use the bounded grouped query.
- Updated the README, public query reference, and design-evolution notes. Added
  [a public Plan 004.4 tutorial](../../notebooks/public/plan-004.4-grouped-queries-and-duplicates.ipynb)
  covering immutable bounds, bounded group/member materialization, complete
  summaries, deterministic ties, empty-file groups, lazy evaluation, an
  exercise, pitfalls, and cleanup using only public APIs.
- Added unit and integration coverage for immutable transformations, internal
  validation, SQL parameterization and bounds, complete pre-limit metrics,
  empty-file groups, deterministic ordering, unknown and unscanned roots,
  successful/failed/interrupted scan behavior, single-scan member consistency,

- User-visible behavior: the new bounded grouped query replaces the Phase 1
