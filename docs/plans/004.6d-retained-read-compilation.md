## Goal

Complete the internal read architecture without adding public query types.
Retain current_scan, current_summary, scan_history, observation_history,
content_for_path, tags_for_content, and tags_for_path with their existing
signatures, return shapes, ordering, exact lookup errors and iterator behavior.

## Implementation boundary

Move their public-read SQL compilation/execution behind narrow functions in
the existing private query modules. Introduce only the immutable descriptions
needed to express exact identity/path/current/history scope; no generic AST or
new service layer. Reuse active assertion and observation materializers and
scan-scope helpers where semantics match. Retained methods can delegate
directly to focused private functions; public fluent objects are not required.

Historical observations retain scan identity and status, including running or
failed history rows, while current reads only use the published successful
scan. Preserve catalog-wide history ordering and cursor-backed lazy consumption.
Exact missing-path/content errors stay distinct from empty search results.

Mutation/reconciliation internals, schema validation, metadata access, and
scan-time summary SQL may remain in Catalog. Do not rewrite transactions or
move mutation-critical validation under this read-only mandate. Where a
read helper is shared with mutations, preserve its behavior and test callers.

## Implementation notes from the current baseline

History generators currently execute at first advancement, but scan_history
and _historical_observations_for_query lack explicit cursor-finally cleanup.
Carry forward 004.4.1's cursor ownership discipline during this extraction:
each iterator owns its cursor, closes it on exhaustion/close/error, and does
not affect other iterators. Keep generator close support and document
contextlib.closing for early exits; a plain break is not guaranteed cleanup.
Do not add history handles, snapshot APIs, or eager history collections.
If correcting this existing cleanup gap as a behavior bug, add its concise
bugfix plan before implementation as required by AGENTS.md.

current_summary currently calls _scan_summary, which is also used during scan
application. Share the pure summary compilation/execution helper where useful
while retaining the mutation-facing wrapper and transaction ownership; do not
leave a second public-read implementation merely to avoid touching that wrapper.
Likewise, _content_record and _content_for_current_path serve tag mutations:
preserve exact validation/error behavior for all callers and leave mutation
orchestration in Catalog. Public read delegation may remain thin Catalog
methods; immutable descriptions are warranted only for actual scope data.

## Acceptance tests

- Public signature/result/error compatibility for every retained read above.
- History iteration remains lazy and deterministic; includes historical
  status and supports close/reopen persistence and cursor cleanup.
- Instrument first advancement, partial close, materialization failure, and
  interleaved history/query cursors; preserve closed-catalog error behavior.
- Current scope excludes failed/interrupted scans.
- Exact path/tag resolution and provenance ordering remain unchanged.
- Public reads use the compiler/executor boundary without duplicate public-read
  filtering or materialization logic in Catalog.
- Mutation and refresh regression tests pass unchanged.
- No schema/source/catalog mutation from successful or failing read terminals.
