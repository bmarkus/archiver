## Scope

Implement CurrentFileQuery.with_tags(limit=3, all_tags=False) and
CurrentFileTagQuery.fetch() exactly as specified in the
[contract](004-public-api-target.md). Keep only fetch on the detail query; counts
and size reductions belong to its base CurrentFileQuery.

Bound file rows in SQLite before fetching distinct alphabetical active tag
previews. Reuse tag previews for duplicate content. All-tags removes only the
tag preview limit for selected parent rows. Pin current scan per fetch.

Migrate ordinary and tag-aware catalog files CLI branches directly to files()
and typed detail views. Preserve the untagged renderer and tagged renderer
behavior, default path ascending / size and date descending, reverse handling,
ascending path tie-breakers, complete totals, option errors and width behavior.

Remove current_files, search_current_files, find_by_content,
search_current_files_with_tags, CurrentFileSearch, TagAwareCurrentFileSearch,
and obsolete CurrentFileSort public alias once callers migrate. find_by_content
callers needing all matches explicitly stream_all() with content.is_(id).
Keep exact content_for_path and path-based tag operations unchanged.

## Implementation notes from the current baseline

CurrentObservationQuery currently scopes SQL through locations.current_scan_id;
it does not store a resolved scan ID. Introduce the narrow internal pinned-scan
scope needed for this multi-statement fetch, reusing its predicate/order
compiler. Do not implement detail views by calling a legacy search or by
re-resolving current state for each statement. Preserve ordinary file terminal
laziness and the independent cursor/handle behavior established in 004.4.1.

Extract the distinct active-tag count/preview logic currently duplicated in
the legacy file/content searches into a private helper usable by 004.6b.
Limit parent observations first; deduplicate their full content identities for
preview loading. Internal database IDs may be used privately, never as public
content identity. Preserve CurrentFileTagView's existing shape.

CLI --all-tags currently reaches legacy searches as tag_limit=None. Translate
it to all_tags=True with a valid numeric default on the new view. With no
requested tags, skip predicate construction (tags.all_of() requires a name).
Keep requested tag display order separate from predicate canonicalization.

Older public notebooks use current_files/find_by_content and retired duplicate
APIs. Their correction may be deferred; neither their execution nor backward
compatibility is a gate for this increment. Preserve semantic coverage in the
automated tests while migrating runtime callers.

## Acceptance tests

- Display-only views without tag filters, untagged rows, duplicates sharing
  previews, zero matches and eager validation of limits/all_tags.
- Provenance-restricted predicates with unrestricted active tag display.
- Row and tag bounds in SQLite; complete tag count versus preview length.
- Base immutable/reusable; views return CurrentFileTagView; filtering/order
  match base fetch; view creation has no database reads.
- Complete file count, distinct content count, and logical file size under bounds.
- Same-scan observation consistency, latest successful scan after failures,
  catalog closure, and source/database unchanged on failure and success.
- Deterministically publish a new successful scan between detail statements;
  selected observations remain from the original scan. Query reuse sees the
  later scan; duplicate streaming lifecycle regressions remain passing.
- CLI existing exact output tests, all-tags wrapping, overflow, narrow widths,
  cross-option errors, and direct query construction.
- Retired names absent from public exports/runtime callers; existing semantic
  tests migrated without losing assertions. Record deferred notebook updates.
