# Bug-fix plans

Each behavior bug receives a concise plan before its fix is implemented.
Use a zero-padded sequential filename such as `001-windows-executable-hashing.md`.

Each plan records:

1. status and summary;
2. reproduction and observed error;
3. root cause;
4. affected invariants;
5. proposed solution and non-goals;
6. acceptance tests; and
7. outcome after validation.

Keep plans proportionate to the fix, but do not omit the evidence or validation
criteria needed to review it safely.
